## 步骤 7：文献全景合成与图谱构建中枢 (Evidence Base Synthesizer) 设计方案 (Map-Reduce 增强版)

### 一、 设计理念

1.  **防溢出架构 (Context Overflow Protection)**：针对动辄几十上百篇文献带来的 Token 超限与幻觉灾难，强制采用 Map-Reduce 架构。先通过并发 Map 节点提取局部子图谱，再通过 Reduce 主节点进行全局综合。
2.  **数据消费者物理隔离 (Consumer Decoupling)**：确立交付物的"三位一体 (The Holy Trinity)"并针对不同受众严格解耦：
    - **可视化图谱 (Graph)**：专供人类与前端 UI 消费，用于直观呈现技术演进与学术战区。
    - **理论框架 (Framework)**：基于“构念池-命题集-机制链-路径图”四步法建构，解释实验现象的逻辑结构。专供阶段 6 (Synthesis Agent) 消费，作为生成论文 Introduction 和 Discussion 的直接叙事底料。
    - **机器数据源 (Downstream Feeds)**：专供阶段 3 / 4 消费，提供强类型的基准模型、指标和工程瓶颈数组。
    - **文献特征表 (Synthesis Table)**：为人类 PI 提供纵向对比的学术台账，由步骤 6 中的三个深析 Skill 协同支撑。
3.  **双语双轨落盘 (Bilingual Persistence)**：严格输出逻辑镜像的 `en_US`（用于 LLM 上下文流转，保证精度）与 `zh_CN`（用于前端展示，降低人类认知负荷）双体系。
4.  **强制溯源与防篡改 (Traceability)**：所有结论必须挂载原文献 `[ID]`，生成防篡改的 `frozen_at` 时间戳。

### 二、 设计方案

#### 文献情报聚合矩阵

| 维度核心模块                 | 核心内容                                                               | 目标下游受众                |
| :--------------------------- | :--------------------------------------------------------------------- | :-------------------------- |
| **可视化图谱 (Graph)**       | 符合前端图谱渲染算法的 `nodes` 和 `edges` 结构，描述演进、继承与对抗。 | 阶段 2 (UI展示/人类PI)      |
| **理论框架 (Framework)**     | 基于构念池、命题集、机制链与路径图的逻辑结构，解释 PI 假说的理论贡献。 | 阶段 6 (论文组装成文)       |
| **文献特征表 (Table)**       | 深度解构文献的理论、方法、结果与启示的纵向对比表。                     | 阶段 2 (人类PI查阅/决策)    |
| **机器数据流 (Feeds)**       | 提取标准 Baseline、Metrics、硬件依赖与工程瓶颈的纯净数组。             | 阶段 3、阶段 4 (机器读取)   |
| **抢发审计 (Scooped Alert)** | 探测是否存在与 PI 假说 100% 撞车的文献。                               | HITL 状态机 (触发 Rollback) |

### 三、 实现流程

| 步骤 | 动作            | 说明                                                                                           |
| :--- | :-------------- | :--------------------------------------------------------------------------------------------- |
| 1    | 情报加载与降噪  | 读取阶段 1 假说，聚合步骤 6 产出的三种结构化 JSON，剔除原文与思维链以极度压缩 Token。          |
| 2    | Map 分片压缩    | 将文献按 10-15 篇分批，高并发调用 LLM 提取局部技术共识与变量。                                 |
| 3    | Reduce 全局合成 | 将子图谱喂入主干 LLM，生成包含三位一体结构的双语大 JSON。                                      |
| 4    | JSON 拆解与落盘 | 将大 JSON 拆解为 `literature_graph_en.json` 与 `_cn.json` 分别落盘，并生成可读 Markdown 报告。 |
| 5    | HITL 挂起       | 检查 `scooped_alert`，挂起状态机等待人类 PI 选择 `[Approve/Retry/Rollback]`。                  |
| 6    | 特征表渲染      | 聚合步骤 6 的深析结果，生成纵向排列的文献特征表 Markdown 文件。                                |

### 四、 输入参数

所有文件集中存放于 `~/.openclaw/workspace-{agent_id}/task/{run_id}/`。

| 参数名             | 类型   | 必填 | 说明                               |
| :----------------- | :----- | :--- | :--------------------------------- |
| **run_id**         | String | 是   | 执行 ID。                          |
| **concurrency**    | Int    | 否   | Map 阶段并发数，默认 8。           |
| **agent_id**       | String | 否   | Agent ID，默认 `evidence`。        |
| **input_agent_id** | String | 否   | 阶段 1 Agent ID，默认 `question`。 |

**必需输入文件**：

- `~/.openclaw/workspace-{input_agent_id}/task/{run_id}/pi_result.json`
- `~/.openclaw/workspace-{agent_id}/task/{run_id}/parsed_papers.json` 及子目录下的 JSON 流。

### 五、 输出参数

**固定输出文件**：

- `literature_graph.json`（完整原始大 JSON，已剪裁掉可视化图谱以优化体积）
- `literature_graph_en.json`（纯英文版引擎驱动数据，不含可视化图谱）
- `literature_graph_cn.json`（纯中文版数据，不含可视化图谱）
- `literature_visualization_graph_en.json`（独立分发的英文可视化图谱数据）
- `literature_visualization_graph_cn.json`（独立分发的中文可视化图谱数据）
- `literature_synthesis_table_cn.md` / `_en.md` / `_cn.json` / `_en.json`（文献综合特征表4份）
- `literature_graph_cn.md` / `_en.md`（人机共读审计报告）

### 六、 文献特征表核心维度与字段定义

文献特征表由步骤 6 中的三个深析 Skill 协同承载，确保对每一篇核心文献进行“降维打击”式的拆解。

| 类别         | 栏目名称                   | 承载 Skill       | 提取重点与用途                                                                             |
| :----------- | :------------------------- | :--------------- | :----------------------------------------------------------------------------------------- |
| **元信息**   | 作者/年份/arXiv ID         | **宏观态势探针** | 唯一标识，便于回溯。**务必注明 v1/v2 等版本号**（arXiv 文章会更新）。                      |
|              | 是否已正式发表 (期刊/会议) | **宏观态势探针** | 标记该预印本是否经过同行评审，后续分析时可加权参考。                                       |
| **理论核心** | 研究问题/目标              | **宏观态势探针** | 一句话总结，用于拼凑领域全景。                                                             |
|              | 核心构念与定义             | **硬核解构引擎** | 自变量、因变量、中介/调节变量及其操作化定义。——直接指导你的实验变量设计。                  |
|              | 理论视角/基础              | **宏观态势探针** | 文章借用了哪个经典理论？这些理论会成为你论文文献综述的主干。                               |
| **方法实证** | 研究范式/实验设计          | **硬核解构引擎** | 范式类型（实验/模拟等）、被试特征、样本量、因子设计。——直接模仿或改进。                    |
|              | 测量工具/指标              | **硬核解构引擎** | 提取量表、行为指标、生理记录装置及信效度。——直接选取你的测量工具。                         |
|              | 关键发现/效应量            | **硬核解构引擎** | 统计显著结果、效应大小（d/η²）、意外发现或零结果。**零结果和负结果同样重要**，能帮你避坑。 |
| **启示反哺** | 对我的实验设计的直接启示   | **价值批判专家** | 具体写出：我可以复用哪个范式？该控制哪个变量？怎样改进刺激材料？                           |
|              | 局限性与未来工作           | **价值批判专家** | 作者承认的不足或你发现的逻辑漏洞。——**研究的机会点和创新切入点**。                         |

#### 7.2 文献特征表示例 (Markdown 纵向排列)

| 栏目           | 内容示例                                                                                |
| :------------- | :-------------------------------------------------------------------------------------- |
| **arXiv 信息** | Doe et al. (2026) arXiv:2301.00001v2 · 未正式发表                                       |
| **研究问题**   | 多任务学习中共享表示对灾难性遗忘的影响                                                  |
| **核心构念**   | IV：任务相似度（余弦距离）；DV：旧任务准确率降幅；中介：特征泛化梯度                    |
| **理论基础**   | 信息瓶颈理论、弹性权重巩固                                                              |
| **实验设计**   | 模拟任务系列，组内：训练序列（交替/集中）× 任务相似度（高/低），被试内平衡              |
| **关键发现**   | 高相似度+交替训练使遗忘减少18%，但学习速度下降（η²=0.14）；极低相似度下集中训练反而更好 |
| **对我的启示** | 采用交替训练范式；将“任务相似度”作为操作检查指标；预注册时需考虑学习速度-遗忘的权衡     |
| **局限/机会**  | 仅用人工合成任务；未考虑情感动机影响——**我的实验可引入真实场景和动机变量**              |
