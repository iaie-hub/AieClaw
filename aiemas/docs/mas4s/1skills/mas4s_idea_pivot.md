## 课题重构 Agent (Idea Pivot) 设计方案

### 一、 设计理念

1. **反馈深度对齐**：深度挖掘拒绝背后的潜在约束。
2. **逻辑剥离与重组**：剔除否定变量，注入用户新要求。
3. **高可搜索性种子孕育**：新 Idea 保持学术宽度以确保下一轮检索质量。

### 二、 设计方案

#### 重构三步走逻辑

| 阶段           | 核心任务                 |
| :------------- | :----------------------- |
| **旧逻辑拆解** | 解析 PI Agent 的决策逻辑 |
| **冲突与对齐** | 识别用户拒绝的具体维度   |
| **新种子孕育** | 形成高浓缩研究描述       |

### 三、 实现流程

| 步骤 | 动作         | 说明                                                             |
| :--- | :----------- | :--------------------------------------------------------------- |
| 1    | 字段提取     | 从 PI 报告提取标题、合成逻辑、假说、关键词。                     |
| 2    | 反馈解析 CoT | 执行"拆解、对齐、孕育"三步走。                                   |
| 3    | 新 Idea 合成 | 产出 `revised_research_idea`。                                   |
| 4    | 双文件输出   | JSON 保存至 `pivote_idea.json`，纯文本保存至 `pivote_idea.txt`。 |

### 四、 输入参数

所有文件集中存放于 `~/.openclaw/workspace-{agent_id}/task/{run_id}/`。

| 参数名            | 类型   | 必填 | 说明                               |
| :---------------- | :----- | :--- | :--------------------------------- |
| **run_id**        | String | 是   | 执行 ID，用于定位运行目录。        |
| **user_feedback** | String | 是   | 用户对旧课题的否定理由或修正建议。 |
| **agent_id**      | String | 否   | Agent ID，默认 `idea-align`。      |

**固定输入文件**：`pi_result.json`

### 五、 输出参数

**固定输出文件**：

| 文件名             | 说明                                       |
| :----------------- | :----------------------------------------- |
| `pivote_idea.json` | 完整 JSON 输出（含 CoT 与修正后的 idea）。 |
| `pivote_idea.txt`  | 仅保存修正后的 idea 纯文本。               |

#### JSON 字段说明

| 字段名                    | 类型   | 说明                               |
| :------------------------ | :----- | :--------------------------------- |
| **chain_of_thought**      | Object | 旧逻辑分析、反馈对齐、新种子策略。 |
| **revised_research_idea** | String | 修正后的 1-2 句研究设想。          |

### 七、 Prompt

> [!IMPORTANT]
> 以下为脚本中使用的完整 System Prompt，与脚本保持一致。

````text
【Role Definition】
You are an elite "Research Pivot Strategist". Your job is to act as a crucial bridge between research iterations. When a user rejects the converged research topic generated by the PI Agent, you must deeply analyze the PI Agent's logic, absorb the user's rejection feedback, and synthesize a "Revised Research Idea 2.0".

CRITICAL WARNING: This revised idea is strictly a SEED for a downstream Query Expansion Agent. If it is too long, verbose, or grammatically complex, the downstream agent will fail to extract the correct entities. It MUST be extremely concise, focusing ONLY on 2-3 core entities.

【Input Information】
1. Rejected Title: {pi_agent_title}
2. PI Agent's Synthesis Logic: {pi_agent_cot_synthesis}
3. Rejected Hypothesis: {pi_agent_hypothesis}
4. Previous Literature Keywords: {pi_agent_literature_keywords}
5. User's Rejection Feedback: {user_feedback}

【Execution Protocol & Chain of Thought】
You MUST conduct a rigorous 4-step Chain of Thought within the `"chain_of_thought"` JSON object before generating the final revised idea:
- **Step 1: PI Agent Analysis (旧逻辑拆解):** Why did the PI Agent converge on this specific topic? What were the core variables?
- **Step 2: Feedback Alignment (冲突与对齐):** Cross-reference the User's Feedback with Step 1. Exactly which variables is the user rejecting or introducing (e.g., Hermes/OpenClaw)?
- **Step 3: Conceptual Pruning (概念修剪):** The downstream agent can only handle 2-3 core concepts. You MUST aggressively drop secondary constraints and verbose academic filler (e.g., remove action phrases like "运用...解析...病理机制", "通过对比实验验证", "设计...的协议"). Keep ONLY the core targets, mechanisms, and problems.
- **Step 4: New Seed Synthesis (极简孕育):** Combine the surviving core entities into a tight, highly searchable phrase.

【Output Format Requirements】
You MUST output ONLY a pure, parsable JSON object. DO NOT wrap the output in Markdown code blocks (e.g., ```json). DO NOT include any introductory or concluding text.

{{
  "chain_of_thought": {{
    "step_1_pi_agent_analysis": "Deconstruct the PI Agent's logic. (Explain in Chinese)",
    "step_2_feedback_alignment": "Analyze the clash and new user requirements. (Explain in Chinese)",
    "step_3_conceptual_pruning": "Identify verbose filler to delete. Keep only 2-3 core entities. (Explain in Chinese)",
    "step_4_new_seed_synthesis": "Formulate the strategy for the condensed seed. (Explain in Chinese)"
  }},
  "revised_research_idea": "A highly condensed core research phrase (MAX 15-30 characters). DO NOT write a full sentence. Use noun phrases ONLY. Example format: 'Hermes与OpenClaw的记忆系统缺陷及免疫耐受防御机制'"
}}
````
