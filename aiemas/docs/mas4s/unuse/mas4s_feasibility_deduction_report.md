# mas4s-feasibility-deduction-report

为了满足科研 SOP 阶段 3 步骤 5 的高标准交付需求，我为您重新设计了**“三位一体”报告生成方案**。该方案将确保输出一份供 PI 深度阅读的 **Markdown 报告**、一份供下游 Agent 自动化解析的 **综合 JSON 报告**，以及一份专门为前端 UI 仪表盘优化的 **可视化 JSON 数据**。

---

### 一、 方案概述 (Overview)

**步骤 5：首席架构审计网关 (Chief Architecture Audit Gateway)** 是阶段 3 的收口节点。它不再产生新的原始数据，而是作为“智库”对前四步（上下文、逻辑、现实、压测）的冲突信息进行全局权衡，并做出最终的准入研判。

**三份交付物定义：**

1.  **综合决策报告 (Markdown)**：叙述性强，包含专家点评、风险警告和降维路线图。
2.  **综合决策报告 (JSON)**：全量结构化副本，包含逻辑模型细节和全量风险矩阵，供阶段 4（实验设计）直接加载。
3.  **可视化态势数据 (JSON)**：高度精简的数值型数据，包含雷达图指标、置信度分数和红绿灯状态，用于 UI 渲染。

---

### 三、 核心执行脚本实现 (Python Implementation)

脚本 `mas4s_feasibility_deduction_architecture_decision.py` 负责调用 LLM，并将返回的 Master JSON 拆解为三份独立的物理文件。

```python
import os

import sys

def export_three_reports(master_data, workspace_dir):
    """三位一体报告分流导出"""

    # 1. 导出综合决策报告 (Markdown) - 供人类 PI 阅读
    narrative = master_data.get("human_narrative", {})
    visual = master_data.get("feasibility_decision_visual", {})
    hitl = visual.get("hitl_status", {})
    status_icon = "🟢" if hitl['action'] == "APPROVE" else ("🟡" if hitl['action'] == "RETRY" else "🔴")

    md_content = f"""# {narrative.get('title_cn')}

## {status_icon} HITL 决策建议：**{hitl.get('action')}** (置信度: {hitl.get('confidence', 0):.2f})
> **审计网关预警：** {hitl.get('gateway_warning')}

---

### 1. 执行摘要 (Executive Summary)
{narrative.get('executive_summary_cn')}

### 2. 架构蓝图审计 (Architecture Blueprint)
{narrative.get('architecture_blueprint_cn')}

### 3. 现实查证与极限压测结论 (Reality & Stress Audit)
**组件与合规性：** {narrative.get('reality_check_findings_cn')}
**物理性能边界：** {narrative.get('stress_test_bottlenecks_cn')}

### 4. 标准化降维方案 (Compromise Roadmap)
{narrative.get('compromise_roadmap_cn')}

---
*Generated by MAS4S Science Assistant*
"""
    with open(os.path.join(workspace_dir, "feasibility_decision_report.md"), "w", encoding="utf-8") as f:
        f.write(md_content)

    # 2. 导出综合决策报告 (JSON) - 供下游 Agent 解析
    logic_payload = master_data.get("downstream_logic_payload", {})
    with open(os.path.join(workspace_dir, "feasibility_decision_logic.json"), "w", encoding="utf-8") as f:
        json.dump(logic_payload, f, ensure_ascii=False, indent=2)

    # 3. 导出可视化态势数据 (JSON) - 供 UI 渲染
    with open(os.path.join(workspace_dir, "feasibility_decision_visual.json"), "w", encoding="utf-8") as f:
        json.dump(visual, f, ensure_ascii=False, indent=2)
```

### 四、 设计亮点总结

1.  **架构解耦**：Prompt 负责“脑力聚合”，Python 脚本负责“格式分流”。LLM 不直接写 Markdown，而是提供结构化素材，由脚本拼装，彻底解决了 Markdown 嵌套在 JSON 中导致的转义崩溃问题。
2.  **下游友好**：`feasibility_decision_logic.json` 被设计为高度结构化的指令集，阶段 4 的实验设计 Agent 可以直接读取 `compromise_params` 来动态调整它的变量循环范围。
3.  **UI 极致优化**：单独分离出 `feasibility_decision_visual.json`，包含了 UI 开发所需的全部元数据（得分、颜色、阈值），无需前端再去正则解析长文本。
