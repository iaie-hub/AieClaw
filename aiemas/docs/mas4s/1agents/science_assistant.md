# 串行链式·双锚点科研 SOP

**Serial Chained · Dual-Anchor Scientific Research SOP**

## 阶段流转链

**Question → Evidence → Architecture → Validation → Analysis → Synthesis**

**中文对应：** 问题锁定 → 证据底座 → 架构决断 → 试点验证 → 可复现分析 → 系统综合

**流转标识：** `Q → E → A → V → An → S`

---

## 核心机制

### 底层铁律

1. **单向状态机流转**：工作流严格按 `Q → E → A → V → An → S` 单向执行。
2. **逆向流转**：仅通过明确的 `[Rollback]` 指令触发，携带 `target_stage` 与 `fatal_error_log`。
3. **强类型数据落盘**：上游输出进入下游前必须通过 JSON Schema 校验。
4. **架构解耦**：高层编排 Agent 不直接调用外部 API，所有工具交互封装在子 Agent 中。
5. **思维链路透明**：所有 Agent 输出最终结果前必须输出 `<think>...</think>` 内部推理过程。

### HITL 三轨制人类锚点

每个阶段挂起等待人类决策时，系统暴露三种标准操作路由：

| 指令             | 触发条件                   | 状态路由                                                                          |
| ---------------- | -------------------------- | --------------------------------------------------------------------------------- |
| **`[Approve]`**  | 当前输出完全符合预期       | 冻结并落盘当前阶段数据，状态机指针跃迁至下一阶段                                  |
| **`[Retry]`**    | 输出有瑕疵或需补充约束     | 拦截落盘，清空当前结果，状态机原地重启。携带 `human_feedback` / `new_constraints` |
| **`[Rollback]`** | 当前困境源于上游根本性错误 | 废弃临时态数据，强制退回指定历史阶段。携带 `target_stage` 与 `fatal_error_log`    |

---

## 六阶段详细规范

### 阶段 1：Question（问题锁定）

**目标**：将模糊想法转化为边界清晰、有创新潜力、可证伪的科学问题。

**核心步骤**：

- 接收初始构想，多角度发散推演 3–5 个候选研究问题。
- 按 FINER + 可证伪性框架评分排序。
- 为胜出项构建完整 PICO/PEOS 框架与假设声明（H₀/H₁）。

**现实锚点**：

- 检索主流数据库标记重叠度，排除已被充分研究的“红海”课题。
- 输出《创新性评估简报》含证据差距声明。

**人类锚点**：

- `[Approve]`：冻结选题 → 流转至 Evidence。
- `[Retry]`：补充约束重新生成 → 原地循环。
- `[Rollback]`：下游致命缺陷回打 → 解析 `fatal_error_log` 后 Pivot 避坑重选。

---

### 阶段 2：Evidence（证据底座）

**目标**：构建透明、可复现、无偏的系统文献综述与理论底座。

**核心步骤**：

- 按 PRISMA 规范生成系统检索方案（数据库/检索式/纳排标准）。
- 执行检索去重，输出 PRISMA 流程图与文献池。
- 提取关键信息形成《文献特征表》与《理论框架草案》。

**现实锚点**：

- 强制 DOI/元数据核验，死链与虚假记录剔除报警。
- 交叉比对撤稿数据库，标记已撤稿文献。

**人类锚点**：

- `[Approve]`：确认底座 → 流转至 Architecture。
- `[Retry]`：补充检索某学者或领域 → 原地循环。
- `[Rollback]`：证据空白不足或已被抢发 → 携带《支撑力度评估》打回 Question。

---

### 阶段 3：Architecture（架构决断）

**目标**：制定可执行、无歧义的研究方案，冻结方法学，确保效度与伦理合规。

**核心步骤**：

- 假说精细化：变量定义与操作化（自变量/因变量/控制变量）。
- 设计定型：研究类型、抽样策略、样本量计算（功效分析）、偏倚控制。
- 统计计划预指定（SAP）：主/次要结局、统计模型、缺失数据处理方案。
- 生成伦理申请初稿，完成预注册模板。

**现实锚点**：

- 扫描仪器/试剂/数据源/软件包的可及性与合规性（License 冲突检查）。
- 验证统计方法在领域内的接受度。
- 输出四维（技术/数据/法理/逻辑）《通用风险矩阵》。

**人类锚点**：

- `[Approve]`：冻结方案与伦理提交令 → 流转至 Validation。
- `[Retry]`：注入资源预算约束重调设计 → 原地循环。
- `[Rollback]`：存在致命缺陷 → 打回 Question 换题 或 Evidence 寻替代方法。

---

### 阶段 4：Validation（试点验证）

**目标**：小规模试点验证全流程可行性，优化后严格执行正式数据采集。

**核心步骤**：

- **4a – 试点**：按 10%–20% 正式规模运行全流程，评估操作可行性、工具信效度、效应量初步估计。
- **4b – 修正**：根据试点结果调整样本量或操作细节，冻结最终操作手册。
- **4c – 正式实施**：严格执行最终方案，全程记录原始数据与元数据（时间戳/操作者/环境参数）。

**现实锚点**：

- 数据采集系统内置范围校验，异常值实时标记。
- 数字实验记录本时间戳锁定，修改全程留痕。

**人类锚点**：

- `[Approve]`：试点可行批准正式启动 → 数据达标流转至 Analysis。
- `[Retry]`：试点暴露操作流程问题 → 原地重试。
- `[Rollback]`：效应量远低预期或工具信效度不可接受 → 打回 Architecture。

---

### 阶段 5：Analysis（可复现分析）

**目标**：透明、可重复地执行预设分析，客观产出结果，不做过度推断。

**核心步骤**：

- 按 SAP 完成数据清洗、离群值判定，冻结分析代码。
- 运行主分析与预设敏感性/亚组分析，探索性分析明确标注。
- 生成符合期刊标准的图表，输出《分析报告》（纯结果陈述）。

**现实锚点**：

- 分析环境容器化（Docker/renv），代码/依赖/随机种子锁定，确保一键复现。
- 自动比对输出与 SAP 的一致性，未预声明分析高亮警示。

**人类锚点**：

- `[Approve]`：结果完整（含阴性） → 流转至 Synthesis。
- `[Retry]`：补充稳健性检验或变动图表 → 原地重跑。
- `[Rollback]`：数据质量根本缺陷 → 打回 Validation 重采甚至 Architecture 修正。

---

### 阶段 6：Synthesis（系统综合）

**目标**：基于所有前置阶段的纯净数据，构建逻辑严密、依规排版的学术论文初稿。

**核心步骤**：

- **强制写作顺序**：方法 → 结果 → 讨论 → 引言 → 摘要。
- AI 仅允许使用前序阶段输出，所有陈述句自动标注数据来源。
- 讨论遵从结构化模板（主要发现→文献异同→推测标记→局限→意义）。
- 依目标期刊模板自动排版，参考文献由阶段 2 文献池生成。

**现实锚点**：

- 沙盒断网环境下生成，杜绝联网编造。
- 内置语法/科学写作风格检查，仅建议不自动改写。
- 参考文献逐条 DOI 可查验，无撤稿文章。

**人类锚点**：

- `[Approve]`：逐字审阅确认论证完整、数据无误 → 产出最终送审稿。
- `[Retry]`：框选局部重写 → 原地循环。
- `[Rollback]`：证据链有缺口 → 打回 Analysis 补分析甚至 Validation 补实验。

## Schema 体系设计

为确保前端可读性与 LLM 解析效率，输入/输出 Schema 采用双语分层设计：

| 层级                | 语言 | 用途                 | 示例路径                                         |
| ------------------- | ---- | -------------------- | ------------------------------------------------ |
| 输入 Schema         | 英文 | LLM 解析、阶段间流转 | `/schemas/input/question_input.schema.json`      |
| 输出 Schema（英文） | 英文 | LLM 解析、阶段间流转 | `/schemas/output/question_output.schema.json`    |
| 输出 Schema（中文） | 中文 | 前端展示、用户审阅   | `/schemas/output/question_output.zh.schema.json` |

所有输入 Schema 仅包含英文键名，输出同时产出一份英文版和一份中文版，分别落盘。前端读取中文版渲染，Agent 间传递使用英文版。

## 全局流转状态机

```
Question ──[Approve]──→ Evidence ──[Approve]──→ Architecture ──[Approve]──→ Validation ──[Approve]──→ Analysis ──[Approve]──→ Synthesis
    ↑                        ↑                         ↑                          ↑                        ↑
    └──[Rollback]────────────└──[Rollback]─────────────└──[Rollback]──────────────└──[Rollback]────────────┘
```

- 所有 `[Retry]` 在当前阶段形成内部闭环，不触发指针跃迁。
- `[Rollback]` 携带 `fatal_error_log` 与 `target_stage`，允许跨多阶段跳回。
- 流转至 Synthesis 的 `[Approve]` 标志系统完成，产出最终送审稿。
