# OpenClaw 会话重置 (Session Reset) 实现方案分析

## 核心流程概述

在 OpenClaw 中，用户通过 `chat.send` 发送 `/reset` 或 `/new` 命令时，系统并不会简单地清空当前会话的内容，而是通过 **“会话旋转 (Session Rollover)”** 机制，为一个物理会话键 (SessionKey) 分配一个新的逻辑会话 ID (SessionID)。

这一过程涉及网关 RPC 层、自动回复分发层以及会话状态管理层。

---

## 逐层分析

### 1. 接入层：RPC 调用 (`chat.send`)

**路径**: `src/gateway/server-methods/chat.ts`

当用户在界面（Web、TUI、Discord 等）输入 `/reset` 时，请求到达网关的 `chat.send` 方法：

- **消息预处理**: 网关首先清洗消息（过滤非法字符、附件等）。
- **参数解包**: 网关将 `sessionKey` 和 `message` 封装进 `MsgContext` 模板上下文。
- **发送逻辑**: 调用 `dispatchInboundMessage` 进入核心逻辑流程。

### 2. 分发层：逻辑路由 (`dispatchInboundMessage`)

**路径**: `src/auto-reply/dispatch.ts` -> `src/auto-reply/reply/dispatch-from-config.ts`

分发层负责处理钩子 (Hooks)、路由 (Routing) 和 ACP (代理协作平台) 特殊逻辑：

- **ACP 预检**: 检查是否需要绕过 ACP 分发（对于某些核心命令）。
- **调用回复解析器**: 最终调用 `getReplyFromConfig`。

### 3. 会话管理层：核心触发 (`initSessionState`)

**路径**: `src/auto-reply/reply/session.ts`

这是重置逻辑的 **骨干部分**。在正式生成 AI 回复之前，`initSessionState` 会被调用：

- **触发器检测**:
  系统检查输入是否命中 `resetTriggers`（配置中的触发词，默认为 `/new` 和 `/reset`）。
- **权限验证**:
  调用 `isResetAuthorizedForContext` 确保发送者有权重置会话（例如管理员或会话所有者）。
- **会话旋转 (Rollover)**:
  如果触发重置：
  1. **生成新 ID**: 立即生成一个新的 UUID 作为 `sessionId`。
  2. **存档旧记录**: 将旧的会话信息存入 `previousSessionEntry` 并触发 `archiveSessionTranscripts` 异步整理磁盘上的旧转录文件。
  3. **状态持久化**: 在会话商店中更新该 `sessionKey` 指向新的 `sessionId`。
- **状态继承**:
  为了保持连贯体验，系统会有选择地将一些行为覆盖从旧会话带入新会话：
  - `thinkingLevel` (思维深度)
  - `verboseLevel` (详细程度)
  - `modelOverride` (模型覆盖)
  - `authProfileOverride` (认证配置)

  **但会显式清空**:
  - `totalTokens` / `inputTokens` (Token 计数)
  - `estimatedCostUsd` (预估成本)
  - `memoryFlushContextHash` (内存刷新哈希)

### 4. 执行层：后续指令

**路径**: `src/auto-reply/reply/get-reply.ts`

- **重置标志**: `initSessionState` 返回的 `resetTriggered` 标志会指导后续行为。
- **Hooks 通知**: 如果是新会话，会并发触发 `session_end` (旧) 和 `session_start` (新) 插件钩子。
- **尾部随行文字**: 如果用户输入的是 `/reset 帮我写个简历`，系统会在重置完成后，将 `帮我写个简历` 作为新会话的第一条消息驱动 AI。

## 关键技术点

### ACP 模式下的原地重置 (In-place Reset)

对于绑定了 ACP (Agent Collaboration Platform) 远程代理的会话，OpenClaw 支持在不更换本地 SessionID 的情况下重置远程代理状态。这通过 `shouldBypassAcpResetForTrigger` 进行判断，使得远程协作更加丝滑。

### 异步存档

重置后，旧的转录文件由 `archiveSessionTranscripts` 异步处理，确保不会阻塞用户的下一条指令。
